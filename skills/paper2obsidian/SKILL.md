# paper2obsidian

PDFの原文を要約・翻訳せずにMarkdown化して保存する。変換・書誌データ取得・リンク・保存・保存後の検査は `scripts/run.py` が1回で行う。Markerの抽出結果は、下記の冒頭・見出しの整理を除いてそのまま使い、図の分割や読み順の乱れなどの小さな誤りは直さない。本文の通読や原本との照合はしない。

## 準備

- 保存先は環境変数 `PAPER_SAVE_VAULT_ROOT`。未設定なら設定を依頼し、保存を進めない。テスト保存の依頼では空の作業用Vaultを作り `--vault-root "<test-vault>"` を付ける。元のVaultは変更しない。
- Marker（`uv tool install marker-pdf`）が必要。スクリプトはMarkerと同じPythonで実行する。`scripts/` はこのスキルからの相対パス。
- 文字化けするPDFやスキャンPDFのOCRには llama.cpp の `llama-server` が必要（PATH上、または環境変数 `LLAMA_CPP_BINARY`）。

```bash
PY="$(sed -n '1s/^#!//p' "$(command -v marker_single)")"
"$PY" scripts/run.py "<input.pdf>" --work "<新しい作業ディレクトリ>"
```

論文のDOIが1ページ目に印刷されていない場合は `--doi`、ネットワークを使わない場合は `--offline` を付ける。

## 結果

- **終了コード0（`"status": "saved"`）**: 保存と検査まで完了している。下記「冒頭と見出しの整理」をしてから報告する。
- **終了コード2（`"status": "review"`）**: `<work>/review.md` の項目を `<work>/draft.md` に1回で反映し、`"$PY" scripts/run.py --work "<work>" --resume` で保存してから「冒頭と見出しの整理」をする。
  - **metadata**: Crossrefに記録がない。まず `draft.md` の冒頭を1ページ目の画像と見比べ、単語が途中で切れるなど本文が崩れていれば、PDFの文字データが壊れているので、frontmatterを書かずに新しい作業ディレクトリで `--ocr always` を付けて実行し直す。崩れていなければ、1ページ目の画像から frontmatter（`title`・`authors`・`year`・`doi`・`source`・`citekey`）を書き、末尾に `## PDF`（`[Original PDF](<assets/{SanitizedTitle}/{SanitizedTitle}.pdf>)`）と `## BibTeX`（コードブロック）を足す。`title` は保存名にも使う。`citekey` は第一著者姓＋年＋タイトル先頭語（a/an/theを除く）。保存名は `scripts/paper_common.py` の `sanitize_title()` で求める。不明な値は創作しない。
  - **text**: OCRが必要だが実行できなかった。ユーザーに llama.cpp の導入を依頼し、本文は直さない。
- **終了コード1**: エラー。同名ノートが既にある場合も停止するので、退避・削除はユーザーの指示に従う。

## 冒頭と見出しの整理

### 冒頭の整理

保存したノート（出力JSONの `note`）の、Introduction（序論）の冒頭2段落までだけを読む。Introductionがなければ、Abstract・Keywordsの後にある最初の本文節の冒頭2段落まで読む。本文節を判別できなければ、ノートの冒頭100行までに限定する。この範囲で、frontmatterと重複するものと1ページ目の欄外の文のうち、削除対象と確実に判断できるものだけを1回の編集で消す。本文の他の部分は読まない。見出しの整理では、以下に従って見出し行だけを別途確認できる。

- 消す: 題名の見出し、著者欄（名前・所属・メール・ORCIDのリンク）、ACM Reference Format などの引用表記、学会名・会期、著作権・ライセンス表記、1ページ目の脚注（★・†などの記号と、研究の経緯・責任著者・連絡先）。
- 残す: 図とキャプション、Abstract、CCS Concepts、Keywords、本文。
- 欄外の文が序論の段落の途中に挟まっていた場合は、消したあと前後の段落を1つの段落につなげる。文言は変えない。
- 削除した題名・著者欄・出版情報の前後に残った余分な空行も、同じ編集で整理する。frontmatterと最初の本文要素（図を含む）の間は空行1行にする。空行の整理は削除箇所の周辺に限定し、コードブロックや本文中の意図的な改行は変更しない。

### 見出しの整理

冒頭の整理と同じ編集で、ノート全体の見出し階層を整える。frontmatterとコードブロックを除き、見出し行だけを確認する。本文の通読や原本との照合は行わない。

- Abstract・CCS Concepts・Keywords、本文の主な章、References・PDF・BibTeXは `##` に揃える。論文の題名の見出しは冒頭の整理で削除するため、残る章を `#` にしない。
- 章番号で階層を判断できる場合は、`1` を `##`、`1.1` を `###`、`1.1.1` を `####` とし、それより深い階層も同じ関係で揃える。番号がない見出しは、見出し行と前後の見出しから階層を確実に判断できるものだけ揃え、不明なものは元の階層を保持する。
- `#` の数と、その直後の半角スペースだけを変更する。見出しの文言・章番号・強調記号・リンク・ブロックIDを保持し、本文・キャプション・参考文献項目を新たな見出しにしない。

編集前後の差分だけを確認し、frontmatter・図とキャプション・Abstract・CCS Concepts・Keywords・本文を誤って削除していないことを確かめる。あわせて、冒頭や削除箇所に余分な空行が残っていないこと、見出しの文言を保持したまま階層が整っていることを確認する。誤削除があれば、その変更だけを戻す。その後、次のコマンドで参照先を再検査する。PDFの再変換やネットワーク通信は行わない。

```bash
"$PY" scripts/run.py --work "<work>" --verify-only "<出力JSONのnote>"
```

終了コード0（`"status": "verified"`）なら検査完了。終了コード1（`"status": "invalid"`）なら検出された問題を報告する。保存時の `problems` は再検査の `problems` に置き換えて報告する。JSONが返らない実行エラーでは、再検査できなかった旨とエラー内容を報告する。

報告は、ノートのパス、`citekey`、図の保存数（`images`）、参考文献の既存/未保存/リンクなしの件数を簡潔に示す。`problems` が空でなければその内容を、`unlinked_with_reason`・`missing_numbers`・`duplicate_numbers` があれば一言添える。直す必要はない。

## 処理の中身

- 変換: PDFの文字データで変換し、"�"（文字化け）・文字データなし・語の2割以上の欠落のいずれかの場合だけOCRでやり直す。
- 書誌データ: 最初の2ページのDOI、なければ題名で Crossref を検索し、題名が原本と一致した記録から frontmatter・`## PDF`・`## BibTeX` を作る。サムネイル（`figure`）は本文で最初の、ある程度大きい画像。
- References: 番号付き（`[1]`、`1.`）の参考文献だけ1項目1行にして `^ref-N` を付け、本文の `[53]` を項目へのリンクにする。DOIの登録題名が原文にある項目は論文ノートへのリンクにする。番号のない形式はMarkerの出力のまま残す。詳細は [references/linking.md](references/linking.md)。
- 保存後の検査: 画像・PDF・サムネイルの参照先が存在し、作業ディレクトリへの参照が残っていないこと。
