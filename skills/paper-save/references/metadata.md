# メタデータとBibTeX

Docling実行前に、まず原本PDFから正式英語タイトル、出版年、DOI、著者名、掲載先を確認する。所属はauthorsへ含めない。通常はPDF内の情報を優先し、ネットワーク照合は不足または曖昧な項目がある場合だけ行う。Docling変換後に矛盾が見つかった場合は保存せず、原本PDFまたは公式情報と照合してメタデータ、`SanitizedTitle`、citekeyを確定し直し、重複確認を再実行する。

## 取得モード

### 通常の高速モード

次の順で取得する。

1. PDF本文、表紙、埋め込みメタデータからタイトル、著者、年、DOI、掲載先を確認する。
2. DOIが確認できた場合は `https://doi.org/<DOI>` へ正規化する。正規化だけではネットワークアクセスを行わない。
3. 必須項目が欠けている、またはPDF内の情報が曖昧な場合だけ、公式URLまたはDOI登録機関のメタデータを1回取得する。
4. 取得に失敗した場合は再試行せず、PDFから確認できた値だけを使う。不明な値は空欄にし、推測で補わない。

高速モードでは、PDFに書かれていないURLを検索して公式ページを探す処理は行わない。

### 厳密な公式照合モード

ユーザーが「公式情報も確認」「メタデータを厳密に照合」などと明示した場合だけ使用する。PDFにDOIがある場合は、次の優先順で公式情報を照合する。

1. 出版社または会議・ジャーナルの公式ページ
2. DOI登録機関が返すメタデータ
3. 論文の公式公開ページ

URLの発見にはCodex web searchを使い、未知のページの取得と構造化抽出には `ax` を使う。まず `ax <url> --outline` または `--locate` で構造を確認し、必要な箇所だけを抽出する。JavaScriptレンダリングが必要なSPAではブラウザツールへ切り替える。

検索結果のスニペットや第三者の文献一覧だけを根拠にしない。PDFとのタイトル、著者、出版年の一致を確認する。公式情報がPDFと矛盾する場合は登録前にユーザーへ確認する。

DOIがなくても、PDFに公式URLが明記されていれば同じ基準で照合してよい。公式情報を取得できない場合はPDFとDocling出力だけを使い、推測で項目を補わない。

## frontmatter値

- `title`: 正式英語タイトル。原文の大文字小文字を保持する。
- `year`: 4桁の整数。不明なら空文字列 `""`。
- `doi`: `https://doi.org/...`。不明なら空文字列 `""`。
- `authors`: 著者名のみを論文と同じ順で並べる。不明なら空配列。
- `source`: 会議名またはジャーナル名。不明なら空文字列 `""`。
- `citekey`: `references/naming.md` の規則で作成する。

## BibTeX

公式ページがBibTeXを提供する場合は、それを優先し、keyだけを命名規則へ合わせる。提供されない場合は公式メタデータから適切なentry typeで生成する。

公式情報を取得できない場合もBibTeXセクションは省略しない。PDFから確認できた項目だけで最小BibTeXを生成する。entry typeを特定できなければ `@misc` を使う。値が不明なフィールドは作らず、推測値や `情報なし` を入れない。

最終BibTeXは互換性のため次の規則で正規化する。

- `pages` の数値範囲は `1--16` のようにASCIIハイフン2個で表す。Unicodeの `–` や `—` を範囲区切りに使わない。
- 曲線アポストロフィ `’` と曲線引用符 `“”` は、BibTeX値内で対応するASCIIの `'` と `"` に置き換える。
- citekeyはfrontmatterの `citekey` と完全一致させる。
- DOIフィールドは `10...` の裸のDOI、URLフィールドは `https://doi.org/...` とする。
- 著者名やタイトルに必要な非ASCII文字まで削除しない。

```bibtex
@misc{author2026title,
  author = {...},
  title = {...},
  year = {2026}
}
```
